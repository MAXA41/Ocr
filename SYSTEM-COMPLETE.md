## 📚 Структура БД

### Основные таблицы:

```sql
product_categories
├─ id UUID PRIMARY KEY
├─ name_uk TEXT (категория на укр. языке)
├─ fields JSONB (поля для формы)
├─ variant_options JSONB (опции вариантов)
├─ is_active BOOLEAN
└─ display_order INTEGER

product_catalog_items
├─ id UUID PRIMARY KEY
├─ name TEXT
├─ description TEXT
├─ category UUID (FK product_categories)
├─ price INTEGER
├─ is_available BOOLEAN
└─ extra_data JSONB (дополнительные поля)

product_variants
├─ id UUID PRIMARY KEY
├─ product_id UUID (FK product_catalog_items)
├─ variant_values JSONB ({"color": "#000000"} или {"size": "M"})
├─ image_url TEXT
├─ price INTEGER (цена варианта)
├─ stock_quantity INTEGER
└─ is_active BOOLEAN
```

## 🔐 Безопасность

### RLS Policies (Row Level Security):

Все таблицы защищены:
- ✅ `product_categories` - PUBLIC READ, ADMIN WRITE
- ✅ `product_variants` - PUBLIC READ, ADMIN WRITE
- ✅ `product_catalog_items` - PUBLIC READ, ADMIN WRITE

### Аутентификация:
- ✅ Telegram бот использует JWT token (проверка через `--no-verify-jwt`)
- ✅ Веб-админ-панель использует VITE_SUPABASE_ANON_KEY (публичный)
- ✅ Все операции логируются в `audit_logs` таблице

## 📈 Аналитика

### Встроенное логирование:

Все добавления товаров логируются:
```sql
SELECT * FROM audit_logs 
WHERE table_name = 'product_catalog_items' 
ORDER BY created_at DESC;
```

Поля:
- `table_name` - какая таблица изменена
- `operation` - INSERT, UPDATE, DELETE
- `new_values` - новые значения
- `changed_by` - кто сделал изменение
- `created_at` - когда
- `telegram_notification_sent` - было ли уведомление в Telegram
