## 🏗️ Архитектурное решение:

### Слой данных (Supabase):

```
product_categories
├─ Определяет структуру для каждого типа товара
├─ Хранит поля формы в JSONB
├─ Хранит опции вариантов (color, size и т.д.)
└─ Пример: Аксесуари → [Бренд, Матеріал, Варіант: Колір]

product_catalog_items
├─ Основные данные товара
├─ Ссылка на категорию
└─ Дополнительные поля в extra_data JSON

product_variants
├─ Для каждого товара может быть несколько вариантов
├─ Каждый вариант хранит: значение, цену, фото
└─ Пример: Кофемашина → Red (#FF0000), Black (#000000)

variant_definitions
└─ Справочник доступных значений вариантов
```

### Слой приложения (JavaScript):

```
site.js
├─ Основная логика сайта
├─ Загрузка товаров
└─ Управление корзиной

product-variants.js (НОВЫЙ)
├─ fetchProductVariants() - загрузка вариантов из БД
├─ renderVariantButtons() - отображение кнопок выбора
└─ Обработчики кликов для обновления фото/цены

admin-product-form.html (НОВЫЙ)
├─ Веб-интерфейс для добавления товаров
├─ Динамическая генерация полей
└─ Загрузка фото на Supabase Storage
```

### Слой интеграции (Edge Functions):

```
telegram-bot (ОБНОВЛЕН)
├─ /add - добавление товара через Telegram
├─ /start - главное меню
├─ /list - список товаров
└─ /stats - статистика

get-categories
└─ Получить структуру категорий (для админ-панели)

upload-product-image
└─ Загрузить фото на Supabase Storage

telegram-audit-logger
└─ Отправлять уведомления об изменениях
```

## 🔐 Безопасность и доступ:

### Row Level Security (RLS):

```
product_categories:
  - ✅ PUBLIC: SELECT (читать может каждый)
  - ✅ ADMIN: INSERT, UPDATE, DELETE (писать может админ)

product_catalog_items:
  - ✅ PUBLIC: SELECT (читать может каждый)
  - ✅ ADMIN: INSERT, UPDATE, DELETE (писать может админ)

product_variants:
  - ✅ PUBLIC: SELECT (читать может каждый)
  - ✅ ADMIN: INSERT, UPDATE, DELETE (писать может админ)
```

### Аутентификация:

```
Веб-админ-панель:
  - Использует VITE_SUPABASE_ANON_KEY (публичный)
  - RLS настроена на основе is_admin флага
  
Telegram бот:
  - Edge Function webhook (нет polling)
  - JWT проверка (--no-verify-jwt флаг)
  - Сохраняет все операции в audit_logs
```

## 🚀 Как это работает:

### Сценарий 1: Добавление через веб-форму

```
1. Пользователь откроет admin-product-form.html
                    ↓
2. Форма загружает категории через get-categories
                    ↓
3. Пользователь выбирает "Аксесуари"
                    ↓
4. Форма показывает поля: Назва, Опис, Бренд, Матеріал
                    ↓
5. Пользователь добавляет варианты (3 цвета)
                    ↓
6. При нажатии "Зберегти":
   - Загружает фото на Supabase Storage (upload-product-image)
   - POST основной товар на product_catalog_items
   - POST для каждого варианта на product_variants
   - Автоматически создает SKU
                    ↓
7. Товар появляется в БД и на сайте
```

### Сценарий 2: Добавление через Telegram

```
1. Пользователь отправляет /add боту
                    ↓
2. Telegram отправляет вебхук на Edge Function
                    ↓
3. telegram-bot/index.ts обрабатывает команду
                    ↓
4. Функция вызывает getCategories()
                    ↓
5. Бот показывает кнопки категорий пользователю
                    ↓
6. Пользователь выбирает категорию
                    ↓
7. Бот запрашивает поля пошагово:
   - Назва товару?
   - Опис?
   - Ціна?
   - Бренд?
   - Матеріал?
                    ↓
8. Функция saveProductFromBot() сохраняет в БД
                    ↓
9. Бот отправляет подтверждение с ID товара
```

### Сценарий 3: Просмотр на сайте

```
1. Пользователь откроет товар (product.html?id=prod-456)
                    ↓
2. site.js загружает основные данные товара
                    ↓
3. product-variants.js запускается автоматически
                    ↓
4. fetchProductVariants() загружает варианты из БД
                    ↓
5. renderVariantButtons() показывает кнопки цветов
                    ↓
6. При клике на цвет:
   - Меняется изображение (на фото варианта)
   - Меняется цена (цена варианта)
   - Подсвечивается кнопка
                    ↓
7. При добавлении в корзину сохраняется выбранный вариант
```

## 📈 Расширяемость:

### Как добавить новую категорию:

**Вариант 1: Через SQL (для админов)**
```sql
INSERT INTO product_categories (name_uk, fields, variant_options, is_active)
VALUES (
  'Нова категорія',
  '[
    {"id": "field1", "name_uk": "Поле 1", "type": "text", "required": true},
    {"id": "field2", "name_uk": "Поле 2", "type": "textarea", "required": false}
  ]'::jsonb,
  '[
    {"name_uk": "Колір", "type": "color"},
    {"name_uk": "Розмір", "type": "size"}
  ]'::jsonb,
  true
);
```

**Вариант 2: Через API (будущая разработка)**
```
POST /api/categories
{
  "name_uk": "Нова категорія",
  "fields": [...],
  "variant_options": [...]
}
```

### Как добавить новый тип варианта:

Текущие типы:
- `color` - цвета (показываются как цветные кнопки)
- `size` - размеры (показываются как текстовые кнопки)

Можно добавить:
- `material` - материалы
- `capacity` - объемы
- `brand` - бренды
- И любые другие
