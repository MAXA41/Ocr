# Міграція: Додавання підтримки варіантів кольорів

## Переглядайте перед виконанням

Ця міграція розширює таблицю `product_price_overrides` новою колонкою `color_variants` для зберігання інформації про варіанти кольорів товарів.

**Дата міграції:** 2026-10-21

## Крок 1: Виконайте SQL міграцію

Перейдіть до [Supabase Dashboard](https://supabase.com/dashboard) і виконайте наступну SQL команду в SQL Editor:

### Основна міграція (обов'язкова)

```sql
-- Добавляем нову колонку для варіантів кольорів
alter table public.product_price_overrides
  add column if not exists color_variants jsonb default '[]'::jsonb;

-- Добавляем коментар для документування
comment on column public.product_price_overrides.color_variants is 
'Array of color variant objects: [{name: "Black", description: "Dark roast", image_url: "https://..."}, ...]';
```

**Очікуваний результат:**
- Нова колонка `color_variants` створена з типом JSONB
- Стандартне значення: `[]` (пустий масив)
- Міграція успішна ✅

## Крок 2: Перевірьте міграцію

Щоб переконатися, що колонка створена коректно, виконайте:

```sql
select column_name, data_type, column_default 
from information_schema.columns 
where table_name = 'product_price_overrides' 
  and column_name = 'color_variants';
```

**Очікуваний результат:**
```
column_name      | data_type | column_default
-----------------+-----------+----------------
color_variants   | jsonb     | '[]'::jsonb
```

- ✅ `js/site.js` — завантаження та застосування варіантів
- ✅ `css/styles.css` — стилізація нових компонентів
- ✅ `docs/supabase-schema.sql` — шаблон схеми з новою колонкою

## Крок 4: Тест функціональності

Після виконання міграції та оновлення коду:

1. Залогіньтеся у [кабінет](https://ocr.com.ua/account.html)
2. Розкрийте карточку товару в панелі управління каталогом
3. Пошукайте розділ **"Варіанти кольорів"** внизу карточки
4. Натисніть **"+ Додати колір"**
5. Заповніть поля:
   - Назва кольору: `Чорна обпалювання`
   - Опис: `Темна, інтенсивна`
   - URL фото: `images/products/roast-dark.webp`
6. Натисніть **"Зберегти"**

**Очікуваний результат:**
- Варіант кольору збережено в базі даних
- На сторінці товару відображається нова інформація про кольори (якщо інтегровано)

## Откат (якщо щось пішло не так)

Якщо потрібно відкотити міграцію:

```sql
alter table public.product_price_overrides
  drop column if exists color_variants;
```

**Увага:** Це видалить усі дані варіантів кольорів, збережених в колонці!

## Що було змінено

### Структура даних

Варіанти кольорів зберігаються як JSONB масив:

```json
[
  {
    "name": "Чорна обпалювання",
    "description": "Темна, інтенсивна",
    "image_url": "images/products/roast-dark.webp"
  },
  {
    "name": "Світла обпалювання",
    "description": "Яскрава кислотність",
    "image_url": "images/products/roast-light.webp"
  }
]
```

## Комумікація з версійністю

Це некритична міграція (новий функціонал, зворотнісний сумісне):
- Стара версія коду працюватиме й без color_variants колонки
- Нова версія коду ігнорує масиви, якщо колонка не існує
- Варіанти кольорів — опціональна функція на більшість товарів

## Питання та підтримка

Якщо виникли проблеми:

1. Перевірте, що SQL команда виконана без помилок
2. Очистіть кеш браузера (Ctrl+Shift+Delete)
3. Перезавантажте сторінку (Ctrl+Shift+R)
4. Перевірте консоль браузера (F12 → Console) на помилки JavaScript
5. Перевірте права доступу в таблиці `catalog_admins`
