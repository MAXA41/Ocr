## Розпорядок міграції

1. **Резервна копія** (5 хвилин)
   - Переконайтеся, що резервна копія Supabase актуальна

2. **SQL міграція** (2 хвилини)
   - Виконайте SQL команду з `color-variants-migration.md`
   - Перевірте, що колонка створена

3. **Оновлення коду** (миттєво)
   - Git pull або переконайтеся, що всі файли на місці
   - Перезавантажте сайт/панель управління

4. **Тестування** (10 хвилин)
   - Залогіньтеся в панель управління
   - Додайте тестовий колір до товару
   - Збережіть та перевірте в БД
   - Очистіть тестові дані

5. **Деплой** (залежить відCI/CD)
   - Якщо використовуєте GitHub Pages/CI:
     - Git commit і push змін
     - Чекайте завершення GitHub Actions
     - Перевірте, що сайт оновлено

## Можливі проблеми та рішення

### Проблема: Помилка "relation does not exist"
**Причина:** SQL міграція не виконана  
**Рішення:** Виконайте SQL команду в Supabase SQL Editor

### Проблема: Інтерфейс не показує кнопку "Додати колір"
**Причина:** Кеш браузера  
**Рішення:**
```bash
Ctrl+Shift+Delete  # Очистити кеш
Ctrl+Shift+R       # Жорсткі оновлення сторінки
```

### Проблема: "Failed to save product price overrides"
**Причина:** Помилка при збереженні в Supabase  
**Рішення:**
1. Відкрийте F12 → Console
2. Перевірте повідомлення про помилку
3. Переконайтеся, що в таблиці `catalog_admins` ваш email

### Проблема: Варіанти не зберігаються
**Причина:** JSON парсинг не пройшов  
**Рішення:**
1. Перевірте консоль браузера на помилки
2. Переконайтеся, що всі поля заповнені коректно
3. Перезавантажте панель управління
